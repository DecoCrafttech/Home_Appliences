## Failures found and fixed during QA

- A Continue button could become a submit button during its own click: gave step actions distinct element identities and added a synchronous submission guard.
- Default address loading could be skipped after appliance selection: check address-field dirtiness instead of the entire form.
- A pending draft timer could recreate a cleared successful draft: suspend draft saving while submitting.
- Tablet Tamil navigation and small-screen admin sidebar could widen the document: corrected responsive breakpoints and grid minimum widths.
- PostgreSQL DATE serialization shifted the selected day in the server timezone: preserve DATE as text through the driver and test the exact date roundtrip.
- Exact accessible naming was missing on the feedback handling selector: added a direct accessible label.
- Test fixture cleanup now tolerates a closed browser context and uses unique service names. Removed the one stranded fixture from an earlier timed-out run; ordinary customer records were not targeted.

## External configuration and remaining acceptance gates

- Google Cloud still rejects the local origin. The OAuth client owner must register `http://localhost` and `http://localhost:5173`.
- Reverse geocoding is implemented behind a server-only Google Maps key. With no configured key, the customer gets a clear manual-address fallback; successful real provider lookup has not been verified.
- Set approved `SERVICE_PIN_PREFIXES` before public launch. Without an approved geographic policy, requests remain enquiries requiring executive coverage confirmation; confirmed serviceability is not claimed.
- Preferred windows are configurable, not capacity-backed technician slots. Assignment and confirmed appointments are persisted; automatic technician matching and capacity scheduling are not implemented.
- Secure object attachment upload/custom profile photo was not exposed because the existing storage upload lifecycle is unverified. Google avatar fallback works.
- Production MFA delivery and public HTTPS hosting remain deployment prerequisites.

Diagnostic handling: an early URL-parsing diagnostic printed the development connection URL in its error output. Subsequent diagnostics redact connection values. Rotate the credential shown by that diagnostic before sharing execution logs.

Final visual follow-up: replaced cramped horizontal admin mobile navigation with a collapsible menu. The added open/navigate/close test passed; the final browser suite is 25/25. Admin typecheck, lint and production build were rerun successfully.
